# Frozen Teacher–Student transfer, efficiency and robustness protocol

Locked before the new measurements on 2026-09-25. No training, architecture, target, threshold, NMS, ROI, graph, decoder, phenotype geometry, GT, Core/Diagnostic membership or V4 test changes are allowed. The final Student-B checkpoint is registered in `STUDENT_B_FREEZE.md`; the Route B Teacher-direct and Student-B must use the same frozen point-conditioned graph, local decoder and `phenotype-geometry-v1`. Existing 16-plant V4 **val** pilot only: Core 12 primary, Diagnostic 4 reported separately. The existing phenotype-first comparison is reused without rerunning or changing its GT matching.

## 1. Knowledge-transfer audit

Use the frozen Teacher-direct and Student-B saved `points.csv`, the frozen 16-image selection, the frozen private GT and authoritative `frozen_pilot_20260924_v5_final` phenotype matching. Do not select images or point correspondence thresholds based on the new outcome. For each plant, report both point counts and one-to-one spatial correspondence in the 518-pixel model canvas. Primary match: Hungarian minimum-distance assignment with maximum distance `0.025 ×` the image's frozen automatic-support bbox diagonal (the locked graph projection scale). A supplementary `0.05 ×` sensitivity result may be reported, but cannot replace the primary assignment. Unmatched Teacher points are removed; unmatched Student points are Student-only. Confidence is descriptive, not a new selection threshold.

Reconstruct each graph with the existing evaluator and `projection_ratio=0.025`; use the exact frozen ROI and point source. A point participates in graph iff its point ID appears among accepted learned nodes. A graph node participates in a phenotype path iff it is the recorded base/tip node or its projected pixel lies within 2 model pixels of a saved full base-to-tip skeleton path. Record projection rejection and merged duplicate separately. Validate reconstructed graph/decode counts against existing frozen output for all 16 before attributing a causal stage. If reconstruction does not reproduce, report the discrepancy rather than silently reinterpret it.

Operational, non-exclusive explanatory labels: `true_point_preservation` (matched Teacher/Student point supporting a GT-matched path); `noise_suppression` (Teacher-only point not supporting a GT-matched path, with no attributable GT loss); `rare_structure_loss` (Teacher point supporting a GT path absent from Student, especially terminal/base support); `new_useful_point` (Student-only point supporting a GT path absent from Teacher); `new_false_point` (Student-only point supporting a prediction without a matching GT path, except count-only/no-curve GT ambiguity); `topology_consequence` (point change propagates to graph node, terminal/base choice, path count or GT correspondence). These are **diagnostic attributions**, not ground-truth point labels. Ambiguous cases remain `unresolved`, not forced into a category.

For each of the two Diagnostic GT paths Teacher matches but Student misses, record the first supported failure stage in order: `point generation → point filtering/projection → graph → decoder → phenotype matching`. A stage is not blamed merely because its output has fewer elements: preserve actual node IDs, terminal decisions and frozen matching evidence.

## 2. Efficiency benchmark

Hardware: the same `cv` RTX 3090 and the existing `adaptive_kp` environment; record GPU name/driver, CUDA, torch, CPU and system RAM, and confirm no competing GPU job. Only the 16 locked val inputs in identical `phenotype_roi_v1` 518×518 RGB form. Both models loaded once per isolated benchmark process; initialization and checkpoint I/O excluded from timed per-image stages. Use `torch.inference_mode()` and synchronise CUDA before/after each timed stage. Do not batch images or change teacher transforms or Student threshold.

Measure (a) point generation from an in-memory focused RGB image through the frozen method's point output—Teacher's existing nine-view structural/representation/consensus path versus Student's single forward/decode; (b) shared graph + local decoder from frozen saved points and the same focused input, including required structural support but excluding point generation and file I/O; (c) end-to-end phenotype from the same focused input through point generation, graph, decoder and locked 240-point phenotype geometry. Report preprocessing exclusion explicitly and never call the result total image-file-to-output latency. Warm up each method/stage for 2 complete 16-image passes, then run 10 complete passes (`N=160` per method/stage), seed `20260925` for fixed image and method order. Report per-method per-stage median, Q1, Q3, IQR, N, and paired per-image speed ratios; no speed claim without measured ratios. Run each method in a fresh process for comparable peak resident memory; sample process RSS during the timed pass and `torch.cuda.max_memory_allocated` after resetting the peak counter. Record both baseline and peak GPU/RAM. Never use a benchmark run to change model settings.

## 3. Perturbation robustness

Run each frozen method on the same 16 identity images and exactly three deterministic perturbations, once each: `flip_horizontal` and `rotate_10` from the project's existing `g1.make_transforms`, plus RGB brightness factor `0.85` (the locked Student training-augmentation lower bound). Apply geometric transforms consistently to the image and ROI/basal masks; inverse-map points and full paths to the identity canvas before comparing. No arbitrary noise, blur or extra strengths. For Teacher, rerun the original nine-view consensus on each perturbed input; for Student, use the original single-view forward/decode. No GT is used to choose perturbations or repair outputs.

Primary point repeatability is one-to-one F1 within the existing `0.05 ×` bbox-diagonal radius after inverse mapping. Report absolute point-count change, exact path-count agreement, the fraction of identity paths matched to a perturbed path under the existing frozen path-matching rule, and symmetric relative length difference of those matched paths using unchanged `phenotype-geometry-v1`. Report branch-angle difference only when both matched paths have valid branch angles; unmatched paths stay in denominators for coverage, not in conditional length/angle medians. Summarize Core and Diagnostic separately; this is **perturbation robustness**, not external generalization. The 16 pilot GT may be used only after these diagnostics for the already frozen scientific comparison, never to select a transform, threshold or checkpoint.

## 4. Final method gate

Use the pre-existing phenotype-first pilot plus these three diagnostics. Only A/B/C are permitted: A, clear Student phenotype benefit; B, phenotype comparable with clear measured efficiency, robustness or deployment value, labeled learned surrogate/knowledge-distilled adaptive keypoint detector; C, no clear phenotype or practical value, Teacher-direct becomes main method and Student remains a learnability/distillation experiment. Do not create a fourth result by training again. Uncertainty or a missing benchmark must be reported as an unpassed gate, not as an invented advantage. V4 test remains locked; its protocol is a separate future preregistration after user review.

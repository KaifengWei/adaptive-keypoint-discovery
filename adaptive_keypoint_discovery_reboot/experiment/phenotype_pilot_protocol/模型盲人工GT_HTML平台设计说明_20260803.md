# 模型盲人工 GT HTML 平台设计说明

- 设计版本：`html-design-v2`
- 状态：设计已冻结，代码尚未实现
- 对应协议：`phenotype-first-pilot-v2`
- 页面用途：在不显示模型输出、预期叶数或 dataset_id 的条件下，从标准化原图建立人工结构路径 GT

## 1. 数据包隔离

正式构建时生成三个测量包：Rater 1 round 1、Rater 1 round 2、Rater 2 round 1。每个包只包含：

- 重新命名为 opaque blind ID 的原图；
- HTML、CSS、JavaScript；
- 不含 dataset_id 的随机顺序清单；
- 导出与恢复所需的空 schema。

管理员目录单独保存 `blind_id_admin_mapping.csv`，不得复制到测量包。Rater 1 两轮的 blind ID、文件名和随机顺序均不同。正式页面文件及其源代码中禁止出现：`v4_val_`、`visible_leaf_count`、`teacher`、`student_B`、`student_D`、旧路径评价或任何方法输出路径。

## 2. 页面进入状态

进入一张图时只显示：当前匿名编号、原图、描迹工具、共同基点工具、叶片动态列表和必要的质量字段。页面不显示预期叶数，不创建任何 GT 行，也不预填 `leaf_exists=yes`。

测量者先标共同地上部基点，再逐次点击“添加叶片”。每次添加只创建一个随机 `trace_uuid` 和空画布图层；测量者需要显式选择：

- `measurable`：描绘从共同基点到叶尖的完整中心结构路径；
- `visible_unmeasurable`：确认有叶，但无法可靠完整描迹；
- `remove_trace`：误加项目，删除且不计入叶数。

系统不提供“应有几片叶”的提示，也不限制可添加条数。

## 3. 描迹交互

- 原图默认适合窗口显示，可一键查看原始像素和缩放。
- 折线点支持添加、拖动、撤销、重做和删除；坐标始终保存为原图像素坐标。
- 第一控制点必须吸附到本株共同基点；终点由测量者放在相应叶尖中心。
- 可标记遮挡等级、是否插值、置信度和备注。
- 页面实时显示 `structural_path_length_px` 与 `structural_path_length_bbox_norm`，正式名称始终显示为“基部—叶尖结构路径长度”。
- 页面不显示毫米结果，避免把扫描元数据写入测量者原始层；metadata-derived mm 在 GT 冻结和管理员解盲后统一计算。

## 4. 提交与身份赋值

提交前，页面执行以下检查：共同基点已定义；每个 `measurable` trace 至少有起点和叶尖；首点与共同基点一致；不可测叶填写原因；不存在未完成的空 trace。

提交时：

1. 锁定当前株的 trace 集；
2. 根据共同基点到叶尖的顺时针极角排序，赋 `GT01、GT02...`；
3. 按协议中的确定性 tie-break 计算 `reference_main_path`；
4. 输出不含 dataset_id 的原始 CSV 和 JSON；
5. 生成提交时间、schema 版本和 SHA-256；
6. 提交后只允许查看，不能静默修改；需要返工时创建带原因的新 revision，保留旧记录。

## 5. 原始导出字段边界

测量者原始导出允许包含：`protocol_version`、`blind_id`、`rater_id`、`measurement_round`、`trace_uuid`、提交后 GT ID、状态、像素坐标、trace 点列文件、像素长度、bbox 对角线与归一化长度、主路径标志、角度/转角、遮挡、插值、置信度、备注和完整性哈希。

禁止包含：`dataset_id`、`pilot_group`、旧可见叶数、源路径、Teacher/Student/Decoder 标识、预测路径、方法误差以及旧人工审计结论。`leaf_exists` 不设默认值；动态 trace 的存在本身表示测量者主动发现了叶片，可在提交时由显式状态派生。

## 6. 管理员解盲与换算

管理员映射表使用密码学安全随机 ID，至少 12 位、去歧义字符集、全包碰撞检查。映射包含 `blind_id、dataset_id、rater_id、measurement_round、image_alias、randomized_order、package_id`，独立保存并计算 SHA-256。

完成全部测量后，管理员脚本可在不输出 `dataset_id` 的前提下生成随机 `adjudication_pair_id`，把同一原图的多轮记录配入方法盲裁决包；裁决者只见匿名配对，不见数据集身份或方法输出。完成裁决和 GT 冻结后，管理员脚本才执行正式解盲：

1. 校验各原始导出 SHA-256；
2. 合并映射恢复 dataset_id 与 Core/Diagnostic 分组；
3. 从锁定 selection metadata 加入 600 dpi、resize scale 和 `mm_per_output_px`；
4. 计算 `structural_path_length_mm_metadata`，统一写入 `scale_provenance=scanner_metadata_600dpi` 与 `scale_label=derived from scanner metadata`；
5. 生成解盲人工 GT，并冻结 SHA-256；
6. 此后才允许载入 Teacher-direct、B、D 结果。

## 7. 离线恢复与协作

页面使用浏览器本地存储按 `package_id + blind_id` 保存未提交草稿，并允许导入先前导出的 JSON 恢复。Rater 1 round 2 的包使用独立命名空间，不能读取 round 1 草稿。导出文件名只含 package、blind ID、rater 和轮次，不含 dataset_id。

同事参与时只接收其测量包与操作说明，不接收管理员映射、选样表、模型结果或其他测量者轨迹。

## 8. 实现验收门槛

正式人工描迹开始前必须全部通过：

1. Core 12 + Diagnostic 4 数量和图片哈希与锁定清单一致；
2. 三个包的 blind ID 唯一、不可逆，Rater 1 两轮不复用；
3. 静态扫描测量包，`v4_val_`、`visible_leaf_count`、方法名和 dataset_id 命中数均为 0；
4. 新开页面时叶片列表为空，`leaf_exists` 无默认值；
5. “添加叶片—描迹—提交—GT编号—导出—恢复”离线走通；
6. 原始 CSV/JSON schema 验证通过，坐标能映射回原图；
7. 确定性主路径规则在等长、近等长和完全同值的合成用例上结果一致；
8. mm 只在管理员解盲层生成，并附 `derived from scanner metadata`；
9. 不读取 V4 test，不载入 Teacher/Student/Decoder 输出。

达到以上门槛后，先提交实现验收摘要供用户确认，再开始正式描迹。

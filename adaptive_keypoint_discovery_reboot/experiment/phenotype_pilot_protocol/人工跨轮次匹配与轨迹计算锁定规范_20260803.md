# 人工跨轮次匹配与轨迹计算锁定规范

- 版本：`phenotype-geometry-v1`
- 状态：`locked_before_formal_GT`
- 适用对象：人工 GT、Teacher-direct、Student-B、冻结 Student-D 的 phenotype 评价层
- 边界：本规范只统一测量与评价，不修改任何 Teacher、Student、graph、decoder 或阈值

## 1. 冻结方法公平性

Teacher-direct 与 Student-B 必须使用完全相同的冻结点条件 graph、局部叶宽尺度 decoder 和下述 phenotype 几何算子。二者唯一允许的差异是输入点来源：前者使用冻结 Route B 自动 Teacher 点，后者使用冻结 Student-B 预测点。

Student-D 只作为既有冻结对照读取，不允许重新训练、修补 Teacher、修改 decoder 或调阈值。所有方法都在人工 GT 冻结后才进入比较。

## 2. trace 清理、平滑与重采样

每条路径输入为按基部到叶尖顺序记录的控制点。算法固定如下：

1. 删除与前一点欧氏距离不超过 `1e-6 px` 的连续重复点；不做手工删点、移动平均或结果导向滤波。
2. 以控制点折线累计弧长作为严格递增参数 `s`。
3. 对 `x(s)`、`y(s)` 分别进行 Fritsch–Carlson / PCHIP 形状保持三次 Hermite 插值；两点退化情形使用线性插值。
4. 在 `[0, s_end]` 上等间隔输出固定 `240` 个采样点，包括两个端点。
5. 若 PCHIP 数值失败，仅允许退化为同一累计弧长参数上的分段线性插值，并记录 `resampling_fallback=linear`；不得换用普通三次样条。

该算子与现有方法路径中已经采用的 coordinate-wise PCHIP 和 240 点重采样口径一致。人工轨迹和三种方法的 base-to-tip 完整路径必须重新通过同一评价层算子计算，不能直接混用历史文件中只针对 branch segment 的旧长度字段。

## 3. 长度、转角和主路径

- `structural_path_length_px`：240 点相邻欧氏距离之和。
- `structural_path_length_bbox_norm`：上述像素长度除以 shoot bbox 对角线。
- `structural_path_length_mm_metadata`：解盲层才计算，等于像素长度乘 `mm_per_output_px`，并标注 `derived from scanner metadata`。
- `total_turning_angle_deg`：相邻非零切向量之间无符号转角绝对值之和。
- `mean_abs_curvature_per_px`：总转角弧度除以结构路径像素长度，仅作探索性指标。

`reference_main_path` 按协议 v2 的四级规则确定：结构路径长度最大；1%近似等长时选弦长较大；弦长差不超过 `max(1 px, 0.001×bbox_diag)` 时选顺时针极角较小；仍同值时按 `trace_uuid` 字典序。

## 4. 分化点与角度

对每条非主路径，在240点重采样曲线上执行：

1. 共享判定容差固定为 `tau_shared = max(2 px, 0.01 × shoot_bbox_diagonal_px)`。
2. 从共同基部开始逐点检查该路径到主路径的最近距离；首次连续3个采样点超过 `tau_shared` 时停止，共享段末点取其前一个合格点。若直到叶尖均未连续越界，标为 `divergence_unresolved`，角度缺失。
3. 主路径分化位置取共享段末点在主路径上的最近点。
4. 局部区间固定为 `w = 0.05 × shoot_bbox_diagonal_px`。主轴向量取主路径上从 `s_main-w` 指向 `s_main` 的近端向量；分枝向量取待测路径上从分化点指向 `s_branch+w` 的远端向量。若可用长度不足，缩短到实际区间并记录。
5. 分化角为两向量的无符号夹角，范围 `0–180°`。主路径为 `not_applicable`，不得填0。

## 5. 人工跨轮次/跨测量者叶片匹配

正式 dataset_id 解盲前，管理员只使用匿名技术配对把同一原图的 session 放入一组。匹配只使用人工轨迹几何，不读取模型结果，也不使用长度、角度或曲率数值择优。

对两次 session 中每一对候选 trace，先把完整路径等弧长重采样为64点，计算：

- `tip_norm`：叶尖距离 / bbox diagonal；
- `curve_norm`：两条64点曲线的双向平均最近点距离 / bbox diagonal；
- `polar_gap`：共同基点到叶尖的顺时针极角最小差 / 180°。

两条均可测时：

`cost = 0.55 × tip_norm + 0.30 × curve_norm + 0.15 × polar_gap`。

任一条为 `visible_unmeasurable` 时，不使用曲线项并重新归一化：

`cost = 0.75 × tip_norm + 0.25 × polar_gap`。

硬门槛固定为 `tip_norm ≤ 0.12` 且 `cost ≤ 0.15`。在全部合格候选上使用带 dummy 的 Hungarian 一对一匹配，dummy cost固定为0.15；无合格配对的 trace 记为 `unmatched_session_1` 或 `unmatched_session_2`。数值同值在 `1e-12` 内时，按 `(trace_uuid_session_1, trace_uuid_session_2)` 字典序破同值。不得在看到 MDC95 或方法表现后修改权重、阈值或匹配结果。

## 6. 版本与实现一致性

浏览器端与Python评价端都必须写入：

- `geometry_protocol_version=phenotype-geometry-v1`；
- `resampling_method=pchip_arc_length_240`；
- `angle_protocol=shared_prefix_tau_0.01D_local_interval_0.05D`；
- `cross_session_matching=c55_30_15_tip012_total015_hungarian`。

两端使用合成直线、弯曲线、近等长主路径和分叉路径做一致性测试。正式人工 GT 开始后，上述算法只能修复明确的软件实现错误，不能根据评价结果改定义；任何修复都必须保留原版本与影响审计。
